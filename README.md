# 一閃

竹林で居合と見切りを読み合う、対戦タイミングゲームです。
HTML・CSS・JavaScriptだけで動きます。ビルド作業も追加のライブラリもいりません。

## フォルダの中身

```
web/
├─ index.html              画面の骨組み（タイトルのメニュー、ガチャ画面、一時停止など）
├─ css/style.css           見た目（色、文字、ボタン、ガチャ画面のレイアウト）
├─ js/katana-image.js      初期刀の絵を文字データにしたもの（下の「刀の絵」を参照）
├─ js/game.js              ゲームの中身すべて（判定、演出、CPU、ガチャ、保存）
└─ assets/katana_initial.png  初期刀の絵（背景を抜いたもの。元の絵の確認・差し替え用）
```

外から読み込んでいるのは Google Fonts の文字2種類（Yuji Syuku、Zen Kaku Gothic New）だけです。
ネットにつながっていないと、端末に入っている明朝体とゴシック体で表示されます。

## 動かし方

- **手元で試す**: `index.html` をブラウザで開くだけで動きます。
- **公開する**: フォルダごと GitHub に置いて GitHub Pages をオンにすると、`https://<ユーザー名>.github.io/<リポジトリ名>/` で遊べます。

## game.js の中身（上から順に）

| 区切り | 何をしているか |
|---|---|
| 定数 | 色、決着名とレア度、刀の絵の読み込み |
| 調整値 | 確定したタイミング（溜め800ms、見切り待機400ms など）。`DEF` に入っています |
| 音 | 効果音を、録音ファイルを使わずにその場で合成しています |
| 画面 | 1画面（CPU戦）と、向かい合わせの2画面（二人対戦）の切り替え |
| 構え | 棒人間の関節の位置（立ち、溜め、見切り、斬った後など） |
| 刀 | 30本の刀の銘・由来・色。初期刀の絵の色を変えて作っています |
| 状態 | 試合の進行と勝ち負けの判定（居合、キャンセル、見切り、決着名） |
| CPU | CPU戦の相手。人数が進むほど強くなり、10人目で上限 |
| 描画 | 竹林、棒人間、一閃、結果画面、タイトル画面 |
| 互いに後なし | 後がない状態のステージ変化と、一閃（後なしの明鏡止水）の演出 |
| ループ・操作 | 毎フレームの更新と、ボタンが押されたかどうかの判定 |
| 刀ガチャと刀帳 | ガチャの演出、全部引く、刀帳、刀を持たせる |

## 保存しているデータ

**ログインしていないとき**は、その端末のブラウザの中（localStorage）に保存します。
**ログイン中**は、銭・刀・刀ごとの戦績・CPU戦の最高記録・持たせる刀をアカウント（Supabase）に保存します。
同じログインIDなら、iPad・iPhone・パソコンのどれでも続きから遊べます（下の「アカウントへの保存」）。

| 名前 | 中身 |
|---|---|
| `issen-wallet-v1` | 所持している銭、CPU戦の最高記録 |
| `issen-armory-v1` | 持っている刀と本数、朱・藍が持つ刀、刀ごとの決着の記録 |
| `issen-proto-v1` | 効果音のオン・オフ |
| `issen-moved-v1` | この端末の記録をアカウントへ引っ越した印 |
| `issen-pending-v1:<id>` | 電波が悪くてまだアカウントに届いていない勝ちなど（届いたら消える） |

## 刀の絵

`js/katana-image.js` には、`assets/katana_initial.png` と同じ絵が文字データとして入っています。
ファイルを直接開いたとき、ブラウザの制限で画像の色替えができなくなるのを防ぐためです。

刀ごとに専用の絵を使いたいときは、`game.js` の `KATANA` にある各刀に `img`（読み込んだ画像）を加えると、その刀だけ色替えではなくその絵が使われます。
絵は今の初期刀と同じ向き（左に柄、右に切っ先）で、横長にしてください。

## オンライン対戦（フレンドと1対1）

タイトルの「オンライン」から、ログイン・フレンド・招待・対戦ができます。Supabase の無料プランで動いています。

| ファイル | 中身 |
|---|---|
| `js/online-config.js` | Supabase の URL と公開してよい鍵（publishable key） |
| `js/net.js` | 登録・ログイン、フレンド、オンライン状態（Presence）、招待 |
| `js/online-match.js` | 対戦の通信（時計合わせ、押した瞬間の送受信、切断、結果の照合） |
| `js/online-ui.js`, `css/online.css` | オンラインの画面と招待の知らせ |
| `js/vendor/supabase-2.118.0.js` | Supabase の部品（MIT ライセンス） |
| `supabase/schema.sql` | データベースの表・守り（RLS）・処理。SQL Editor で実行する |
| `supabase/使用量の確認.md` | 無料枠の残りの確かめ方と、招待の止め方 |

### 同期のしかた
- 送るのは「いつ・何を押したか」だけ。二人の端末が同じ計算で判定するので、決着名と勝者は必ず一致します
- 勝ち負けが決まる「斬る瞬間」だけ、相手の「その時刻までの操作は全部送った」という知らせを待ってから演出に入ります
- 試合の最後に二人がそれぞれ結果をサーバーへ報告し、一致したときだけ記録します。食い違えば無効試合です
- 相手から10秒便りがなければ切断として終了（記録なし）。ページを閉じた場合はすぐ相手に伝わります

### アカウントへの保存（銭・刀・戦績）

| ファイル | 中身 |
|---|---|
| `js/save-sync.js` | ログイン中の保存。端末の記録の引っ越し、勝ち・ガチャ・持たせる刀をサーバーへ送る |
| `supabase/save-data.sql` | 持ち物の表、刀の一覧、ガチャの確率、決着の銭、サーバー側の処理。SQL Editor で実行する |
| `tools/katana-sql.js` | `game.js` の刀の一覧から `save-data.sql` の刀の行を作り直す |

- **くじと銭の計算はサーバー**: ガチャはサーバーが引き、勝ちの銭も決着名からサーバーが決めます。画面の数字を書き換えても増えません。1分に30勝より多い記録と、1日5000銭より多い勝負の銭は受け付けません（`app_config.day_coin_cap` で変更可）
- **引っ越し**: ログイン前にその端末で遊んだ記録は、その端末で初めてログインしたときに一度だけアカウントへ足します（1アカウントへ5台まで）。端末の記録は消さずに残し、ログアウトするとそれで遊べます
- **刀は id で保存**: 刀は `mumei` `ruri` のような id で覚えるので、刀を足しても並べ替えても記録は崩れません。刀をガチャから外すときは、行を消さずに `katana_catalog.in_gacha` を false にします（持っている人の刀は残ります）
- **アップデートしても消えない**: `save-data.sql` は何度実行しても持ち物の表（`saves`）にさわりません。硬直などの数値やゲームの見た目を変えても、アカウントの記録はそのままです
- **SQL を実行する前でも動く**: サーバーに処理がまだなければ、ログインしても端末の保存のまま遊べます

#### 刀を足したとき
1. `game.js` の `KATANA` に刀を足す（`id` は英小文字。あとから変えない）
2. `node tools/katana-sql.js` を実行（`save-data.sql` の刀の行が作り直される）
3. Supabase の SQL Editor で `save-data.sql` を実行（実行するまで、その刀はガチャに出ません）

ガチャの確率・重なりの銭・決着の銭を変えたときは、`save-data.sql` の同じ値も直して実行してください（`node tests/save-values-test.js` で食い違いを見つけられます）。

### 番付（フレンドのランキング）と戦闘力
タイトルの「番付」から、自分とフレンドだけの三つの番付を見られます（ログインが必要）。

| 番付 | 値 |
|---|---|
| 戦闘力 | オンライン対戦の結果だけで動く。サーバーが計算する |
| 勝ち抜き | CPU戦の最高記録（`saves.cpu_best`） |
| 刀帳 | 集めた刀の種類の数（`saves.owned`） |

- `supabase/ranking.sql` を SQL Editor で実行する（`schema.sql`・`save-data.sql` の後）。何度実行しても戦闘力（`ratings`）と記録（`rating_log`）は消えない
- 戦闘力は、二人の報告が一致して確定した試合（`matches.status = 'done'`）のときだけ、データベースのトリガーが動かす。ゲームから書き込む処理はない
- 計算: はじめ1000。期待勝率 E = 1/(1+10^((相手−自分)/400))。勝ち +32×(1−E)×連勝倍率、負け −32×E。連勝倍率は1連勝目×1.0から1勝ごとに+0.1、上限×1.5。増減は最低1、100より下がらない。同じ相手とは1日（日本時間）5戦まで数える
- 数値は `rating_config` の表で変えられる（Table Editor で直せばすぐ反映）
- 試合の結果画面に「戦闘力 1056 → 1074 ＋18」と出る（`match_rating`）

### 団体戦（カスタムマッチ）
タイトルの「団体戦」から。ホストが部屋を作り、赤・青（と観戦）に分かれて戦う（ログインが必要、戦う人は10人まで・部屋は16人まで）。

| ルール | 進み方 |
|---|---|
| 大将戦 | 出る順（先鋒・次鋒・三鋒…・中堅・副将・大将）に一戦ずつ。大将の勝ちは2点、ほかは1点。同点なら大将どうしの代表戦。人数が違えば少ない側の誰かが二度出る |
| 勝ち抜き戦 | 出る順に、勝った者が残る。先に全員敗れたチームの負け |
| 自由戦 | 勝ち残り。相手の勝ち残りに挑む人が「挑む」を押した順に戦う。一勝1点、先に決めた点（1〜30）で勝ち。途中でチームを変えられる |
| トーナメント | 赤青に関係なく、出る人全員をくじで組む。不戦勝あり |

- `supabase/team.sql` を SQL Editor で実行する（`schema.sql`・`save-data.sql`・`ranking.sql` の後）。何度実行しても部屋や対戦の記録は消えない
- 各試合は1対1のオンライン対戦（`matches`）をそのまま使い、`matches.room_id` で部屋とつなぐ。試合が確定・中断すると、トリガー（`team_on_match`）が次の組み合わせを決めて次の試合を作る
- 団体戦の試合は戦闘力に数えない（`matches_rating` トリガーに `room_id is null` の条件、`rating_apply` にも同じ確かめ）。銭はいつも通り
- 入り方: 部屋の主のフレンドなら寄合（チャット）の「参陣」や招待から、だれでも部屋番号（6文字）から。合言葉を付けた部屋は、招待された人以外は合言葉が要る
- 出る順は、始まるまで同じチームの人にしか見えない（`team_lineups` の RLS）
- 観戦: 部屋の人は試合のチャンネル（`match:<id>`）を読むだけで入れ、二人の送り物から同じ試合を1.5秒遅れで再生する（`IssenMatch.watch`）。観戦者が増えるとリアルタイムのメッセージ数も増える（1人あたり1試合で数百通ほど）
- 試合が止まったら（通信切れ・食い違い）、部屋の主が「もう一度」か「◯◯の負け」を選ぶ
- 外からの入口: `window.IssenTeam.join(roomId)`（寄合の募集ボタンなどから呼ぶ）
